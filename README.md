# Comparative Analysis of Sequential Models for Mobile Network Traffic Forecasting

One-step-ahead forecasting of Internet traffic on the Milan Telecom Italia
"Big Data Challenge" dataset (Barlacchi et al., 2015), comparing a classical
statistical model, an LSTM, and a Transformer encoder across three
geographical areas.

## Dataset

- Source: [Harvard Dataverse — Telecommunications - SMS, Call, Internet - MI](https://dataverse.harvard.edu/dataset.xhtml?persistentId=doi:10.7910/DVN/EGZHFV)
- 62 daily files (`sms-call-internet-mi-YYYY-MM-DD.txt`), Nov 1, 2013 – Jan 1, 2014,
  tab-separated: `square_id, timestamp_ms, country_code, sms_in, sms_out, call_in, call_out, internet`.
- The dataset must be downloaded manually from Dataverse (requires accepting
  terms of use) and is not included in this repository. Place the downloaded
  zip file(s) somewhere on disk and point `src/manifest.py`'s
  `DOWNLOADS_DIR` / `ZIP_NAMES` at them (or extract the `.txt` files into a
  single folder and adapt `manifest.build_manifest`).

## Setup

```bash
python -m venv .venv
source .venv/bin/activate  # or .venv\Scripts\activate on Windows
pip install -r requirements.txt
```

Tested with Python 3.11. No GPU is required (TensorFlow runs on CPU); see
`reports/tables/timing.csv` for training/inference times on the reference
hardware (8-core CPU, 8.4 GB RAM, no CUDA GPU).

## Pipeline

Run from the project root, in order:

```bash
python src/manifest.py          # sanity-check the 62 daily files are found
python src/memory_demo.py       # naive vs. optimised load, 1 sample day (Section: memory management)
python src/etl.py               # full ETL: all 62 days -> data/processed/*.parquet (~10-15 min)
python src/eda.py               # exploratory analysis figures (Section 2)
python src/tune_lstm.py         # optional: re-run LSTM validation grid on square 5161
python src/run_experiments.py   # 3 models x 3 areas: forecasts, plots, metrics, timing (~40 min CPU)
python tests/test_smoke.py      # lightweight metric / Fourier exog checks
```

Outputs:
- `data/processed/internet_traffic.parquet` — long-format (square_id, timestamp, internet), all squares/days
- `data/processed/total_traffic_per_square.parquet` — total traffic per square (for the EDA distribution figure)
- `data/interim/*.json` — memory, AIC, LSTM/Transformer tuning, and experiment evidence used in the report
- `reports/figures/*.png`, `reports/tables/*.csv` — all report figures and tables
- `reports/report.pdf` — research report (submit this PDF on Canvas)

```
  memory_demo.py         # naive-vs-optimised memory footprint comparison

  model_lstm.py                   # Model 2: stacked LSTM (Keras)
  model_transformer.py              # Model 3: Transformer encoder (Keras)

reports/

tests/
  test_smoke.py
data/interim/                        # committed JSON evidence (memory, tuning, metrics)
data/processed/                      # not committed; generated by ETL
```

## Models

1. **Dynamic harmonic regression + ARMA errors** — Fourier terms for daily
   (period 144) and weekly (period 1008) seasonality as SARIMAX exogenous
   regressors, with a low-order ARMA(3,1) for residual autocorrelation
   (order selected by AIC grid search, see `data/interim/sarima_order_selection.json`).
2. **LSTM** — 2-layer stacked LSTM (64, 32 units) over a 144-step
   (1-day) window of scaled past values.
3. **Transformer encoder** — 2-layer self-attention encoder (d_model=32,
   4 heads) over the same 144-step window, with sinusoidal positional
   encoding and a last-token prediction head.

See the report for full justification, hyperparameter tuning log, and results.
